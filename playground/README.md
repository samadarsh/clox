# clox playground

A static page that runs clox in the browser: clox's C source compiled to
WebAssembly with Emscripten. It is published to GitHub Pages by
`.github/workflows/pages.yml`.

**Features:** a CodeMirror editor with Lox highlighting; errors underlined in
the editor (message on hover) and in the output; a stats bar (time,
instructions executed, GC collections, peak heap); Share (the program goes in
the URL) and autosave; light/dark themes; a phone layout; a **Bytecode** tab
linked to the source; and a **time-travel debugger** that records a run and
replays it step by step, with the value stack and call frames.

| File | What |
|---|---|
| `index.html`, `style.css` | the page |
| `app.js` | editor, Run/Debug/Stop, the Output, Bytecode and Debugger tabs, sharing, theme |
| `lox.js` | Lox syntax highlighting for CodeMirror |
| `share.js` | compressing a program into the URL and back |
| `worker.js` | runs clox in a Web Worker |
| `examples.js` | the example programs in the dropdown |
| `clox_wasm.c` | the WebAssembly entry points (run, disassemble, debug), used instead of `src/main.c` |
| `hooks.h` | the playground's hooks into the VM (see below) |
| `vendor/` | CodeMirror 6, bundled into one file (`codemirror.js`) from pinned versions |
| `clox.js`, `clox.wasm` | generated by `make wasm` (not in git) |
| `test/test_playground.py` | headless Chromium test of the whole page |

## Try it locally

```sh
make wasm-docker                 # or `make wasm` with Emscripten installed
python3 -m http.server -d playground 8000
# open http://localhost:8000
make test-wasm-docker            # or `make test-wasm` with Playwright installed
```

The page has to be served over http: browsers don't run Web Workers, ES
modules or `.wasm` files from `file://` URLs.

## How it works

- **Web Worker.** The C functions run a whole program before they return, so
  they run in a worker, not on the page's main thread: an endless loop keeps
  only the worker busy. Stop (or Esc) terminates the worker, the only way to
  interrupt it, and starts a new one. A second worker only compiles, for the
  Bytecode tab, so that tab keeps working while a program runs.
- **A fresh VM every time.** `clox.wasm` is downloaded and compiled once; every
  Run, Debug or disassembly creates a new instance of it, with its own memory.
- **Hooks into the VM, without changing clox.** The stats and the debugger
  need to see inside the VM. `src/vm.c` and `src/memory.c` call three small
  hooks (`playground/hooks.h`), each inside `#ifdef CLOX_PLAYGROUND`, which
  only `make wasm` defines. Without it the preprocessor removes them: the
  normal build's machine code is byte-for-byte what it was before they were
  added. The hooks only read the VM's state.
- **Bytecode tab.** `clox_disassemble()` compiles without running and prints
  every function with the book's own disassembler (`src/debug.c`), marking
  each instruction's offset and source line, so the page can link the two.
- **Debugger.** `clox_debug()` runs the program with recording on: before each
  instruction, the hook writes the function, offset, line, value stack, call
  frames and the number of lines printed so far into a JSON buffer. After at
  most 20,000 steps it stops the program. The page then replays the recording
  without running anything again: the slider just picks a step. The recorder
  uses the C library's own `malloc`, not clox's `reallocate()`, so recording
  never starts a garbage collection or changes the heap statistics.
- **Sharing.** Share deflate-compresses the program into the URL after `#`
  (which never reaches a server). Edits are autosaved to `localStorage`; after
  an edit, the program is removed from the URL so a reload shows the edit.
- **CodeMirror** is vendored rather than loaded from a CDN: its packages must
  share one copy of `@codemirror/state`, and a single pinned bundle guarantees
  that. To change versions: edit `vendor/package.json`, then
  `cd playground/vendor && npm ci && npm run build`.
