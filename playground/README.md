# clox playground

A static page that runs clox in the browser: clox's C source compiled to
WebAssembly with Emscripten. It is published to GitHub Pages by
`.github/workflows/pages.yml`.

| File | What |
|---|---|
| `index.html`, `style.css` | the page |
| `app.js` | editor, examples, Run/Stop, output panel |
| `worker.js` | runs clox in a Web Worker |
| `examples.js` | the example programs in the dropdown |
| `clox_wasm.c` | the WebAssembly entry point, used instead of `src/main.c` |
| `clox.js`, `clox.wasm` | generated by `make wasm` (not in git) |
| `test/test_playground.py` | headless Chromium test of the whole page |

## Try it locally

```sh
make wasm-docker                 # or `make wasm` with Emscripten installed
python3 -m http.server -d playground 8000
# open http://localhost:8000
make test-wasm-docker            # or `make test-wasm` with Playwright installed
```

The page has to be served over http: browsers don't run Web Workers or load
`.wasm` files from `file://` URLs.

## How it works

- **Web Worker.** `clox_run()` runs a whole program before it returns, so it
  runs in a worker, not on the page's main thread: an endless loop keeps only
  the worker busy. Stop terminates the worker (the only way to interrupt it)
  and starts a new one.
- **A fresh VM on every Run.** `clox.wasm` is downloaded and compiled once;
  each Run creates a new instance of it, with its own memory, and
  `clox_run()` calls `initVM()` and `freeVM()` around the program. A program
  can't see anything a previous one left behind.
- **Output** goes from C's `stdout` and `stderr` to JavaScript callbacks, one
  line at a time. The worker sends it to the page in batches (every 50 ms), and
  stops sending after 1,000,000 characters, so a program printing in a tight
  loop can't flood the page. Errors are shown in red, and each `[line N]` is a
  link that selects that line in the editor.
- **`clock()`** is C's `clock()`; Emscripten implements it with the browser's
  high-resolution timer.
